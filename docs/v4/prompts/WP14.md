# WP14 — wide randomisation of every generated episode (Codex prompt)

## Goal

Generated episodes must not look the same. Today objects start in small fixed rectangles, the arm always starts at home, the expert moves identically, and sizes and physics never change. After this package every episode draws, from its attempt seed: object and goal positions anywhere in the arm's table workspace, object sizes, the arm's start pose, the expert's heights, dwell times and speed, and object mass and friction; DR copies also jitter the camera poses. Starts that fall within one 5 mm / 5° cell of an earlier start are skipped. At the end, a smoke run makes 5 episodes (3 successes, 1 failure, 1 recovery) for each of the 17 tasks.

The contract is `docs/v4/contracts.md` §16 (read all of it). The exact task-table and SO-101 changes are `docs/v4/prompts/WP14_tasks.diff`.

## Decisions (pinned by the tests)

- **Public names.** `core.generate.specs`: exactly `build_spec`, `draw_expert_params`, `draw_physics`, `validate_physics`. `core.generate.fingerprint` adds `near_key` (keep any constants private). `core.tasks.sampling` adds `validate_workspace`, `in_workspace`. `core.generate.specs` must not import `core.expert` (WP6 rule).
- **Field order.** `ObjectState(pose, active, color, size=None)`; `EpisodeSpec` ends with `..., fps, expert_params, physics`; `AppearanceDraw` ends with `camera_offsets`; `ExpertProgram` ends with `speed_scale`.
- **Optional JSON.** Each JSON dataclass may declare a class attribute `_optional` (frozenset of field names). `to_json` omits those fields while falsy; `from_json` accepts them missing. All golden `spec_fp` values stay the same.
- **Draw order inside `sample_start`:** count, colours, slots, size variants, placements, goals, initial pose. A workspace draw outside the clip costs one try.
- **`tcp_fn(q)`** returns a `Pose` of the TCP in the base frame (FK of the arm's chain; `make_spec_fn` builds it).
- **Expert overlay.** `reset(obs, spec)` rebuilds the program from the parsed base program each episode: step `i` gets `params | spec.expert_params["steps"][str(i)]`, objects get the drawn sizes, and the joint, gripper and Cartesian speed limits are multiplied by `spec.expert_params.get("speed_scale", program.speed_scale)`.
- **Near-duplicates** are skipped as `SCENARIO_SEEN`, in both the planner and the generator, so the manifest and resume logic need no change.
- **Arm workspaces.** SO-101: `r_m = [0.15, 0.40]`, `bearing_deg = [-182, 2]`, clip `xy_min = [-0.30, -0.42]`, `xy_max = [0.30, 0.03]` (covers the v3 cube and box positions; the owner confirms reach and camera view in the container). The test arm `fx_arm5l` (fixture, already committed) uses `r_m = [0.16, 0.40]`, `bearing_deg = [-182, -10]`.

## Isaac side (container; no CPU tests, the owner runs them)

1. **Size variants.** `generic_task_cfg` builds one prim per (object, variant) named `<object>__v<k>` (scaled copies of the object's USD/cuboid), parked like inactive objects; `IsaacGenEnv.reset` teleports the variant matching `spec.objects[name].size` to the object's pose and parks the others. Object pose reads, colour sets and the `pick_place_cube` contact sensors follow the active variant (one jaw–cube contact sensor per variant; `PickPlaceTask` signals read the active one).
2. **Physics.** At reset, for each entry of `spec.physics`, set the active prim's mass and its material's static and dynamic friction (Newton/PhysX material API used elsewhere in `sim/envs/mdp`). Missing keys keep the USD values.
3. **Start pose.** `IsaacGenEnv.reset` already writes `spec.initial_q`; check that the arm settles there before the first recorded frame.
4. **Camera jitter.** `dr_replay` (v2 path) gains `--camera_jitter POS_M,ROT_DEG` (default off), passes `camera_jitter` and the env's camera names to `draw_appearance`, and before re-rendering a copy offsets each camera prim's local translation by `position_m` and its local rotation by `rotation_deg` (XYZ Euler, degrees); restore the nominal pose afterwards.
5. **Workspace check.** `tests/sim/check_workspace.py --arm so101 --n 200`: draws positions from `[arm.workspace]`, checks IK reachability from above at the approach height and that the point projects inside the front camera image; prints the failing fraction (target < 2 %).
