# WP12 — dataset post-processing: consolidate, merge, upload, streaming (Codex prompt)

## Goal

Add the Isaac-free post-processing of generated datasets to `src/core/datasets/`: the consolidated sidecar table (`consolidate.py`), the merge of shard datasets into one (`merge.py`), the resumable upload to the Hugging Face Hub or an object-storage bucket behind an injected client (`upload.py`), and the episode selection / streaming helpers (`streaming.py`), plus the two command-line scripts `core/scripts/merge_shards.py` and `core/scripts/upload_dataset.py`. The owner's hard requirements are **no duplicate episodes** and **nothing leaves the machine without a passing audit of exactly what is uploaded**: merge refuses fingerprint collisions, and both merge and upload refuse a missing, failed or stale audit. Follow `docs/v4/contracts.md` §9.2 and §10 exactly; where the contract leaves a choice open, this prompt fixes it and the tests pin it.

The audit itself (`core/datasets/audit.py`, WP7) and MemoryWriter (`core/datasets/frames.py`, WP7) do not exist yet. WP12 reads the audit **record** (`meta/audit_report.json`) through its own private reader and computes the content digest itself (both defined below), and works on the lite on-disk layout of §11 directly. The real LeRobot v0.6.1 merge and streaming APIs are not available on the host: everything that needs them is a lazy import inside one function, and the tests only check that those paths are lazy.

## The audit record and the content digest (`_audit_record.py`)

WP7 will write `meta/audit_report.json` with `write_audit_report`. WP12 reads it itself:

- **Record format** = the §10.1 `AuditReport` fields as one JSON object, exactly the keys `v, root, passed, episodes, checks, content_digest, fingerprints_digest, created_at`; `v == 1`; `passed` a bool; `checks` a list; `content_digest` 64 lower-case hex. A missing file, invalid JSON, a non-object, missing/extra keys or a wrong type → `AuditFailed`. Return a private frozen dataclass with those fields (`checks` as a tuple).
- **Content digest** (§10.1, made exact): `json_sha256({rel: file_sha256(path)})` where `rel` is the posix path relative to the dataset root (e.g. `"data/chunk-000/file-000000.parquet"`) of **every regular file** under `meta/`, `data/`, `videos/` and `task_meta/` (recursively, hidden files included, missing folders contribute nothing), except `meta/audit_report.json`. `json_sha256` from `core.utils.hashing` sorts the keys. Files elsewhere in the root (README, `images/`, `mp4/`, …) do not count. WP7's `content_digest(root)` must produce the same value; the tests compute it with `tree_sha256` per folder.
- **Passing and current** for a report object `r` and a root: `r.passed is True` and `r.content_digest == _content_digest(root)`; otherwise `AuditFailed`. Read only those two attributes (duck typing), so WP7's `AuditReport` works unchanged.

## consolidate.py (§9.2)

- `consolidate(root) -> Path`: read every sidecar with `list_sidecars` + `read_sidecar` (an invalid sidecar raises `SchemaError` before anything is written), build one row per sidecar sorted by `episode_index`, write `<root>/task_meta/episodes.parquet` and return that path. Works for an empty dataset (zero rows, same schema) and creates `task_meta/` if needed.
- **Schema**, in this order (the §9.2 table read top to bottom, left to right), names / arrow types / nullability exact: `episode_index` int64 not null, `num_frames` int64 not null, `attempt_index` int64, `seed` uint64, `kind` string not null, `instruction` string, `failure_mode` string, `furthest_stage` string, `perturbation_type` string, `success` bool, `scenario_key` string, `spec_fp` string, `traj_fp` string, `appearance_fp` string, `episode_fp` string, `source_episode_fp` string, `sidecar_json` string not null. Values: `attempt_index` / `seed` = `attempt.index` / `attempt.seed` (null when `attempt` is null; seeds up to 2**64 − 1 must stay exact), `perturbation_type` = `perturbation["type"]` or null, the five fingerprints from `fingerprints` (null when it is null), `source_episode_fp` = `source["episode_fp"]` or null, `sidecar_json` = `canonical_json(sidecar)`; the rest are the sidecar keys of the same name. Build the table with an explicit `pa.schema` (not pandas).
- **Deterministic**: the same sidecars give a byte-identical file, whatever order they were written in and however often you run it.
- **Atomic**: write to a temporary file **inside `task_meta/`** (hidden name ending `.tmp`, e.g. `tempfile.mkstemp(dir=..., prefix=".episodes.", suffix=".tmp")`), fsync, then `os.replace` onto `episodes.parquet` (call `os.replace` as a module attribute at call time; the tests patch it, and they also patch `pyarrow.parquet.ParquetWriter.write_table`). On any failure remove the temporary file and re-raise; the previous `episodes.parquet` stays byte-identical and no other file appears in `task_meta/`.
- `read_consolidated(root) -> list[dict]`: `FileNotFoundError` if the file is missing; otherwise `json.loads` each `sidecar_json` in row order and `validate_sidecar` it (invalid JSON or an invalid sidecar → `SchemaError`). It returns plain dicts equal to `read_sidecar` output and never rebuilds the file.

## merge.py (§10.2)

**`ShardSummary`** — frozen dataclass `(root, episodes, episode_fps, scenario_keys, report)`; `__post_init__` coerces `root` to `Path` and the two sequences to tuples. Classmethod **`ShardSummary.from_root(root)`** (contract addition): read the audit record (`AuditFailed` if missing/malformed); `list_sidecars` must be exactly `0..E−1` (else `SchemaError`); read every sidecar; a sidecar whose `fingerprints` (or its `episode_fp` / `scenario_key`) is null cannot be merged → `SchemaError`. `episodes = E`; `episode_fps` = every episode's `episode_fp` in index order; `scenario_keys` = the `scenario_key` of the **originals** (`source is None`) in index order — DR copies legitimately share their parent's key (§10.1 `scenario_key_unique_originals`). `report` is the record. Two `from_root` calls on the same root compare equal.

**`MergePlan`** — frozen dataclass `(index_maps: tuple[dict[int, int], ...], total: int)`.

**`plan_merge(shards)`**, checks in this order, nothing written in any case:
1. No shard → `ValueError`.
2. Every shard's report is passing and current for `shard.root` → else `AuditFailed`.
3. Compatibility (`ConfigError`): every shard has `meta/info.json` (missing or invalid → `SchemaError`), and they agree on `codebase_version`, `fps`, `features` and `robot_type` (compare `info.get(key)`, so absent equals absent). `meta/generation_plan.json` (read with `read_plan_json`) is present in all shards or in none; when present they agree on `task`, `config_sha256`, `task_toml_sha256` and `arm_files_sha256`.
4. Duplicates (`DuplicateError`): an `episode_fp` in two different shards; an original's `scenario_key` in two different shards; a manifest line key `(task, kind, attempt_index)` in two different shards' `meta/generation_manifest.jsonl`. Repeats inside one shard are the audit's business, not merge's. A shard without a manifest file has an empty manifest (a shard whose quota was 0 never writes a line).
5. **Canonical order** (contract change, see below): sort the shards by `(plan["shard"][0] if the shard has a generation_plan.json else 0, report.content_digest)`. Offsets are cumulative in that order; `index_maps[k] = {old: offset_of(shards[k]) + old for old in range(shards[k].episodes)}` belongs to `shards[k]` **as listed**; `total` = sum of episodes. So generation shards merge as shard 0, 1, 2, … and the result never depends on the order the shards were listed in.

**`merge_frames(plan, shards, dst_root, repo_id)`** — writes `data/` and `meta/info.json` of the destination (videos too in the LeRobot path):
- `ValueError` if `plan` does not match `shards` (length, or an index map that is not exactly `0..episodes−1`); `GenerationError` if `dst_root/meta/info.json` exists or `dst_root/data` holds anything.
- **Lite shards** (every `info["codebase_version"] == "v3.0-lite"`, §11), on the host with pyarrow: read every `data/**/*.parquet` of a shard and group the rows by `episode_index` (the set of episodes must equal `0..episodes−1`, else `SchemaError`); for each shard in canonical order and each old episode in order, sort the rows by `frame_index`, set `episode_index` to the new index and `index` to a running counter over the merged dataset (contiguous from 0 in new-episode order, like LeRobot's `index += total_frames`), keep every other column and the schema unchanged, and write `data/chunk-000/file-{new:06d}.parquet`. Then write `meta/info.json` = the info of the first shard in canonical order with `total_episodes = plan.total` (`json.dumps(indent=2, sort_keys=True)`, atomically).
- **Otherwise** (real LeRobot v3 shards, container only): `from lerobot.datasets.aggregate import aggregate_datasets` **inside the function** and call it with the shard roots in canonical order (`roots=…`, `aggr_root=dst_root`, `aggr_repo_id=repo_id`, distinct `repo_ids` per source). On the host the import fails with `ImportError` and nothing has been written (the tests check this). After aggregation, check `meta/info.json` `total_episodes == plan.total` (else `GenerationError`).

**`apply_merge_meta(plan, shards, dst_root)`** — writes `task_meta/` and the manifest of the destination:
- Same `ValueError` plan check; `GenerationError` if the destination already has sidecars or a manifest.
- For every shard and old index: `read_sidecar`, set `episode_index` to the new index, `write_sidecar(dst_root, …)`. Nothing else in a sidecar changes (`attempt`, `fingerprints`, `source` keep their values).
- If any shard has a manifest: write `dst_root/meta/generation_manifest.jsonl` (atomically: temporary file in `meta/`, fsync, `os.replace`) = the shards' lines concatenated in canonical shard order, each shard's lines in file order, each line `canonical_json(ManifestLine.to_json()) + "\n"` with `episode_index` mapped through that shard's index map for accepted lines (others stay null). The result reads back with `Manifest.lines()`, no line lost or duplicated, and its accepted lines carry `0..total−1` in file order.
- Do not copy `meta/audit_report.json` (the merged dataset needs its own audit) or `meta/generation_plan.json` (a merged dataset is not a resumable generation root).

## upload.py (§10.3)

**`StorageClient`**: `@runtime_checkable` `typing.Protocol` with `list_files(self) -> dict[str, str | None]`, `upload_file(self, local: Path, remote: str) -> None`, `finalize(self, message: str) -> None`.

**`HubStorage(api, repo_id, *, revision="main", repo_type="dataset")`** over an injected `huggingface_hub.HfApi`-like object (never import huggingface_hub in `upload.py`):
- `list_files()`: `api.list_repo_files(repo_id, repo_type=…, revision=…)`; if non-empty, `api.get_paths_info(repo_id, paths, repo_type=…, revision=…)`; each returned file maps `info.path` to its LFS sha256 (`info.lfs.sha256`, or `info.lfs["sha256"]`; huggingface_hub's `BlobLfsInfo` supports both), or `None` when `info.lfs` is `None` (a regular git file, e.g. `.gitattributes` or a small JSON).
- `upload_file(local, remote)`: `api.upload_file(path_or_fileobj=str(local), path_in_repo=remote, repo_id=…, repo_type=…, revision=…, commit_message=…)` — keyword arguments only (the real method is keyword-only).
- `finalize(message)`: no API call (per-file commits are already final).

**`BucketStorage(fs, prefix)`** over an injected fsspec-like filesystem (`find`, `info`, `put_file`):
- Strip a trailing `/` from `prefix`. fsspec returns paths without the protocol, so compare against the prefix without its `scheme://`.
- `list_files()`: for every path of `fs.find(prefix)` under `<bare prefix>/`, the remote name is the rest of the path; the value is `fs.info(path).get("sha256")`. `_COMPLETE` is not listed.
- `upload_file(local, remote)`: `fs.put_file(str(local), f"{prefix}/{remote}")`.
- `finalize(message)`: write `<prefix>/_COMPLETE` whose content is `message` (UTF-8) via `put_file` from a temporary local file.

**`UploadItem(local, remote, sha256, size)`**, **`UploadPlan(items, skipped)`**: frozen dataclasses; `items` a tuple of `UploadItem`, `skipped` a tuple of remote paths.

**`plan_upload(root, storage, *, allow_overwrite=False) -> UploadPlan`**, in this order (nothing is uploaded by `plan_upload`):
1. Audit (`AuditFailed`): record missing or malformed; not passed; `content_digest` differs from the current digest; `task_meta/episodes.parquet` missing.
2. Hygiene (`GenerationError`, not `AuditFailed`): any regular file whose name ends `.tmp` anywhere under the root; a `mp4/` entry at the root (LeRobotRecorder's `--save_mp4` preview tree, `dataset_root / "mp4"`); any file under `images/` at the root (an open LeRobot episode buffer; an empty `images/` folder is fine).
3. Local files: every regular file under `data/`, `videos/`, `task_meta/`, `meta/`, as posix paths relative to the root (which are also the remote paths). If `len(list_sidecars(root)) >= 1000`, the sidecar files (`task_meta/episode_NNNNNN.json`, exactly the names `list_sidecars` counts) are left out; below 1000 they are uploaded. Do not open or validate the sidecars here.
4. Order: the groups `data/`, `videos/`, `task_meta/`, `meta/`; inside a group sorted by remote path, except that `meta/audit_report.json` comes last of all.
5. Call `storage.list_files()` once. For each file (hash it with sha256, record its size): remote sha256 equal → append the remote path to `skipped`; remote present with a different sha256 → `GenerationError` unless `allow_overwrite` (then plan it); remote present with `None` (unknown) → plan it (no `allow_overwrite` needed: it cannot be proven different); absent → plan it. Remote files that do not exist locally are ignored (never deleted).

**`run_upload(plan, storage, *, message)`**: `storage.upload_file(item.local, item.remote)` for every item in order, then `storage.finalize(message)` once. An exception from the client propagates immediately (no finalize). Rerunning `plan_upload` after a failure skips everything already uploaded, so each file lands exactly once; a run after a complete upload plans nothing.

## streaming.py (§10.4)

- **`select_episodes(rows, *, kinds=None, success=None, exclude_holdout_of=None) -> list[int]`**: pure (never mutates `rows`); `rows` are sidecar dicts as returned by `read_consolidated`. Returns the matching `episode_index` values sorted ascending without repeats. `kinds`: iterable of `Kind` members or their values (`Kind(k)` each; an unknown value → `ValueError`); `None` = all; `[]` = none. `success`: `None` = any, `True` / `False` keep rows whose `success` **is** that value (a null `success` never matches). `exclude_holdout_of`: duck-typed task spec, read only `.holdout.colors` and `.holdout.counts` (WP12 may not import WP1); a row is excluded if any object's `color` is a held-out colour, or if for some non-null object `set` the number of objects of that set is a held-out count.
- **`make_streaming_dataset(repo_id, *, episodes=None, **kwargs)`** (container only): `from lerobot.datasets import StreamingLeRobotDataset` inside the function and return `StreamingLeRobotDataset(repo_id, episodes=…, **kwargs)`, with `episodes` converted to a list of Python `int` (or `None`). On the host it raises `ImportError`.
- **`iter_episodes(root, *, episodes=None) -> Iterator[tuple[dict, dict[str, np.ndarray]]]`** (contract addition, host): yields `(sidecar, frames)` per episode in ascending `episode_index`. Sidecars come from `read_consolidated(root)` when `task_meta/episodes.parquet` exists, else from `read_sidecar` for each `list_sidecars` index. Frames come from every `root/data/**/*.parquet` (pyarrow), grouped by `episode_index` and sorted by `frame_index`; this must work for the lite layout (list columns, one file per episode, shape-(1,) labels as one-element lists) and for real LeRobot v3 files (fixed-size-list vectors, scalar shape-(1,) columns, several episodes per file in any row order). `frames` has exactly the §10.1 `read_frames` keys: `action`, `observation.state` `(N, J)` float32; `label.stage`, `label.imitate` `(N,)` int64; `label.ee_pose` `(N, 7)` float32; `frame_index` `(N,)` int64. `episodes` restricts the output (still ascending; an index without a sidecar → `ValueError`). The set of episodes in the data must equal the set of sidecars, and each episode's row count must equal its sidecar `num_frames` (else `SchemaError`).

## Scripts

Both `main` functions parse with `argparse` (a bad command line exits with `SystemExit(2)`), print a short summary on success and return `0`. Any `GenerationError` (including its subclasses) is caught, printed to stderr as `f"{type(e).__name__}: {e}"`, and `main` returns `1`. Other exceptions (e.g. `ImportError` when a container-only library is missing) propagate.

- **`merge_shards.main(argv=None)`**: positional `shards` (one or more roots), `--dst_root` (required), `--repo_id` (required; used by the LeRobot path). Refuse an existing `--dst_root` (even an empty folder) with `GenerationError` before reading anything. Then `ShardSummary.from_root` for each shard, `plan_merge`, `merge_frames`, `apply_merge_meta`, `consolidate(dst_root)`. On a refusal nothing exists at `--dst_root` and the shards are untouched. The tests require the merged tree to be byte-identical for every listing order of the shards.
- **`upload_dataset.main(argv=None, *, storage=None)`** (the `storage` keyword is a contract addition so tests and callers can inject a client): positional `root`; exactly one of `--repo_id` (Hub) or `--bucket` (an fsspec URL such as `s3://bucket/prefix`) — a required mutually exclusive group; `--revision` (default `main`), `--message` (default `"Upload dataset"`), `--allow_overwrite`, `--dry_run`. With `storage=None` build the real client **inside a private function at call time**: `--repo_id` → `from huggingface_hub import HfApi`; `api = HfApi()`; you may call `api.create_repo(repo_id, repo_type="dataset", private=True, exist_ok=True)` (visibility is an open point, §14); `HubStorage(api, repo_id, revision=revision)`. `--bucket` → `import fsspec`; `fs, _ = fsspec.core.url_to_fs(url)` (or `fsspec.url_to_fs` / `fsspec.filesystem(protocol)`; the test fake provides all three); `BucketStorage(fs, url)`. Then `plan_upload(root, storage, allow_overwrite=…)`; with `--dry_run` print the planned remote paths and stop (no upload, no finalize); otherwise `run_upload(plan, storage, message=…)`.

## Decisions taken where the contract is open or had to change

1. Merge order: §10.2 says offsets are "cumulative in the given order", but the merge must be deterministic whatever order the shards are listed in. Offsets follow the canonical order above; `index_maps` stay aligned with the input. (Contract change.)
2. `ShardSummary.from_root`, `streaming.iter_episodes` and `upload_dataset.main(..., storage=None)` are additions to the public surface.
3. The audit record format and the content digest are fixed above; WP7 must write/compute exactly these.
4. Compatibility mismatches between shards are `ConfigError`; manifest-line collisions are `DuplicateError`; the lite host merge path lives in `merge_frames`.
5. Upload hygiene definitions, `None`-hash semantics, remote extras left alone, `_COMPLETE` content and invisibility, sidecar threshold counted with `list_sidecars`, per-group sorting.
6. Scripts report contract errors with exit code 1.
